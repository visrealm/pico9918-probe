# Pico 2 PICO9918 host-bus probe

This checkout extends the official [Raspberry Pi debugprobe](https://github.com/raspberrypi/debugprobe)
at `3fff5b240ca8200c7ad538cb61c02dfc39bda831`. Select `PICO9918_HOST_BUS=ON`
to retain CMSIS-DAP/OpenOCD and replace the UART interface with a USB serial
host-bus controller. Standard builds with the option OFF retain the UART.

Designed for **one Pico 2 and one PICO9918 or PICO9918 PRO in a ZIF socket**.
Use a second independent probe for another target. No voltage sensing or target
3.3 V connection is used. Optional transistor power control is supported;
the removable VBUS jumper works without it.

## Wiring

Use the prototype drawings in the parent project's `pcb/debug-probe-pico2`.
Data numbering below is conventional byte significance. TI calls our D0 `CD7`.

| Probe GPIO | Pico 2 physical pin | Target signal | Target DIP pin |
|---|---|---|---|
| GP2 | 4 | SWCLK | DBG1.1 |
| GP3 | 5 | SWDIO | DBG1.3 |
| GND | 3 | SWD ground | DBG1.2 |
| GP4..GP11 | 6, 7, 9, 10, 11, 12, 14, 15 | D0..D7, low to high significance | **17..24** |
| GP12 | 16 | /CSR | 15 |
| GP13 | 17 | /CSW | 14 |
| GP14 | 19 | MODE | 13 |
| GP15 | 20 | MODE1 | **11** |
| GP18 | 24 | /INT input | 16 |
| GP19 | 25 | CPUCLK input | 38 |
| GP20 | 26 | GROMCLK input | 37 |
| GP21 | 27 | /RST host reset output | 34 |
| GP22 | 29 | Optional transistor POWER_EN, HIGH on | Switch, not directly to DIP |
| GND | 23 | Ground | 12 |
| VBUS | 40 | USB 5 V through jumper or switch | 33 |

Close the target clock solder bridges when measuring its clock outputs.
Video uses the target's normal FFC/VGA adapter. GP0/1/16/17/26/27/28 are spare.
**Do not move 5 V bus inputs onto GP26..28.** This firmware is for Pico 2, not
the original RP2040 Pico. Its bus outputs are 3.3 V.

The target schematics/BOMs label U5 as **74HC245**, while the prototype discussion
specified HCT. Confirm the fitted part: a 5 V **74HCT245** accepts 3.3 V writes;
a 5 V **74HC245** does not guarantee that input-high margin. If HC is fitted,
observed failures may be voltage-related rather than a firmware timing limit.
The target and probe share USB VBUS; do not also power the target through another
USB supply. `arm manual` assumes its VBUS jumper is connected.

## Build and start

The current upstream sources require **Pico SDK 2.3.0** (`pico_usb_reset`).
From this checkout on the configured Windows machine:

```powershell
./build-pico9918.ps1
python -m pip install -r host/requirements.txt
python host/pico9918_probe.py ports
python host/pico9918_probe.py --port COM8 info
python host/pico9918_probe.py --port COM8 arm manual
```

The build writes `../../build-debugprobe-pico9918/debugprobe_pico9918.uf2`.
Install it on the **probe Pico 2** with BOOTSEL. The build script never flashes
anything. Use `arm switch` instead of `arm manual` only with the documented
BC327-40/2N3904 power switch fitted. Closing the serial port leaves the target
armed, allowing subsequent OpenOCD use. `off`, USB suspend, or USB disconnect
releases bus/SWD pins and turns off the optional switch. With a jumper, `off`
releases signals but cannot physically remove power.

Portable CMake equivalent (SDK, Arm toolchain and native compiler installed):

```sh
cmake -S . -B build -G Ninja -DPICO9918_HOST_BUS=ON -DPICO_SDK_PATH=/path/to/pico-sdk
cmake --build build
```

## Drive the bus and use OpenOCD

```powershell
# Set write address 0, write four bytes, then read them back.
python host/pico9918_probe.py --port COM8 raw WRITE 1 0040
python host/pico9918_probe.py --port COM8 raw WRITE 0 12345678
python host/pico9918_probe.py --port COM8 raw WRITE 1 0000
python host/pico9918_probe.py --port COM8 raw READ 0 4

openocd -f host/openocd-pico9918.cfg -f target/rp2040.cfg
# PRO: use target/rp2350.cfg from a Raspberry Pi-compatible OpenOCD installation.
```

CMSIS-DAP retains the official USB bulk interface. Select a particular probe
with OpenOCD's `adapter serial` when using two. SWD access requires ARM first.
OpenOCD reset is an MCU software reset; `raw RESET 10` drives the separate host
/RST line for 10 ms. Do not halt the target while characterizing normal bus
performance. The probe serializes each SWD packet with each bus operation.

Ports are **0=data, 1=control/status** with MODE1 HIGH. Ports 2 and 3 apply the
same MODE values with MODE1 LOW. Current target firmware ignores MODE1 in its
host PIO decoding, so these are presently aliases, not implemented V9938 ports.

The Python `Probe` class also exposes `read`, `write`, `address`, `register`,
`vram_read`, `vram_write`, `events` and `command` for custom host programs.
Raw operations use up to 256 bytes per command. Timing stress runs entirely
inside the probe and supports **one uninterrupted 16 KB burst**.

### Existing live-test probe replacement

The parent project's `test/live/live9918.py` selects `interface/cmsis-dap.cfg`
and performs flashing, scene setup, capture and measurement over SWD. Neither
it nor the current live runner uses the probe's UART. The new probe therefore
preserves the interface those tests require; their test code needs no change.
From the parent project:

```powershell
python tools/debugprobe/host/pico9918_probe.py --port COM8 arm manual
python test/live/runner.py --board 2040 --probe YOUR_NEW_PROBE_SERIAL --quick
# For PRO, use --board pro and that probe's serial number.
```

The existing `LIVE9918_PROBE_RP2040` / `LIVE9918_PROBE_RP2350` environment
variables can select the replacement persistently. Find its serial with the
host client's `ports` command. Re-arm after USB reconnect or suspend; use
`arm switch` for the optional switched supply. This startup requirement means
the current firmware is **not yet a zero-setup drop-in**. It is expected to be
compatible with the live runner, but that has not yet been physically tested.

The live runner requests 20 MHz SWD by default. The upstream PIO divider
rounds that to 15.625 MHz with this probe's fixed 125 MHz clock; test behavior
is preserved, but end-to-end transfer time need not match the old probe.
Run the existing live tests and destructive bus sweeps separately: both can
alter the same target state. Standalone target-USB test UF2s elsewhere in the
project are a separate transport, not part of this SWD-only live runner.

## Functional checks

These commands overwrite target VRAM and change registers/reset state:

```powershell
python host/pico9918_probe.py --port COM8 --output functional.json test --mode1-alias
```

Checks six full 16 KB patterns, walking data bits, address-line isolation,
14-bit address wrap, read-ahead, status/interrupt assertion and clearing,
host reset, CPUCLK and GROMCLK. `--model 9918|992x|9118|912x` selects expected
clock routing; `--model skip` omits clock checks if bridges are open.
`--mode1-alias` explicitly checks the current legacy behavior on both MODE1
levels. It does not claim extended-port functionality.

## Find the host timing limits

All timing values are **PIO ticks**, each `8 ns * divider` at a fixed 125 MHz
probe clock. Reports include nanoseconds, tested bytes, mismatches and the first
failure. They record every tested point, including islands of failures; they
do not assume a monotonic threshold. Repeat with different seeds and under
the target workloads/video settings you care about.

### Sustained burst rate, pulse width and recovery

`TIMING setup pulse hold divider` controls normal transfers. Setup is from
the data/MODE output update to the falling strobe. Pulse is strobe-low duration.
Hold is from the rising strobe to the next byte's data/MODE update. Thus the
inactive strobe interval is **hold + setup**, and the byte period is
**setup + pulse + hold**. Default `(32,125,125,1)` is 256 ns setup, 1 us low,
and 1 us hold. Valid ranges: setup 5..255, pulse 6..255, hold 6..255, divider 1..64.

```powershell
# First establish conservative passing results.
python host/pico9918_probe.py --port COM8 --output baseline.json sweep pulse --values 125 --repetitions 8

# Decrease byte period, keeping setup and hold fixed. 200 ticks = 1.6 us.
python host/pico9918_probe.py --port COM8 --output speed.json sweep period --values 200:20:-5 --setup 5 --hold 6 --repetitions 8

# Independently sweep strobe pulse width and inactive recovery interval.
python host/pico9918_probe.py --port COM8 --output pulse.json sweep pulse --values 125:5:-5
python host/pico9918_probe.py --port COM8 --output gap.json sweep gap --values 125:10:-5
```

The sweep tests reads and writes separately. Address setup and the other
direction use conservative timing. Before stressed writes, VRAM is poisoned
with the inverse pattern so a missed write cannot pass by leaving old data.
Each repetition uses a different reproducible PRNG seed. Default length is
16 KB; `--bytes` permits shorter uninterrupted bursts to compare length effects.

The reported rate is the **commanded byte rate within the burst**, not a USB
rate and not a guarantee of operation at other voltage/temperature/workload
conditions. Confirm the generated waveform on the prototype: unexpected DMA
starvation can lengthen inter-byte gaps. The minimum representable normal
period is 120 ns (8.33 MB/s commanded), not a measured PICO9918 capability.
Sweep return code 1 means at least one tested point failed, which is expected
when deliberately crossing a boundary; 2 means a command/transport error.

### Read access window with pulse width held constant

```powershell
python host/pico9918_probe.py --port COM8 --output read-window.json edges read-sample --values 4:112:4 --pulse 125
# Late sample, including after /CSR rises at tick 125:
python host/pico9918_probe.py --port COM8 --output read-late.json edges read-sample --values 115,122,129,140,160 --pulse 125
```

`read-sample` is the IN instruction's offset after /CSR assertion. /CSR pulse
width stays fixed while the sample moves. Each trial reads a known randomized
byte after setting its address conservatively. A correct late read can be
charge remaining on a released bus; it does not prove that the target is still
driving it. An oscilloscope is needed to establish output-enable/release timing.

### Write setup, late arrival and hold

```powershell
# Negative = valid data before /CSW falls; positive = valid data after it falls.
python host/pico9918_probe.py --port COM8 --output write-window.json edges write-arrival --values=-64,-32,-16,-8,0,8,16,32,64,100,118 --pulse 125 --hold 32
# Poison the data bus at /CSW rising edge or shortly afterward.
python host/pico9918_probe.py --port COM8 --output write-hold.json edges write-hold --values 0,8,16,32,64 --arrival=-32 --pulse 125
```

The data starts deliberately wrong, changes to the intended byte at `arrival`,
then changes back to the wrong value at `pulse + hold`. Verification uses
conservative reads. Together these locate the acceptance window; changing
only the pulse width would not do that. Each point tries 16 bytes per repetition.

The event sequencer needs at least **8 ticks between output updates**; delay
lengths are 8..4103 ticks. It samples 3 ticks before each event ends. This sets
a 4-tick earliest read sample and leaves a small unrepresentable region around
the /CSR rising edge; invalid points are rejected before running the edge sweep.
Write arrival may coincide with assertion, and zero hold changes data and
deasserts /CSW in the same output instruction. OE changes a tick after the pin
value; the sequencer only permits direction changes with both strobes inactive.

PIO sampling times are instruction-relative, **not calibrated target-pad
measurements**. RP2350's input synchronizers add two system-clock cycles,
and there are GPIO pipeline and wiring delays. Synchronizers remain enabled.
See the [RP2350 datasheet, PIO input synchronization](https://datasheets.raspberrypi.com/rp2350/rp2350-datasheet.pdf).
Use captured relative edges and external scope measurements to calibrate a
particular fixture before interpreting a boundary as an absolute access time.

## Power-up readiness with host reset held low

With the transistor power switch fitted and selected using `arm switch`:

```powershell
python host/pico9918_probe.py --port COM8 arm switch
python host/pico9918_probe.py --port COM8 --output powerup.json powerup --cycles 20 --reset-ms 10
# Compare no reset hold, or a shorter/longer host reset:
python host/pico9918_probe.py --port COM8 --output no-reset.json powerup --reset-ms 0
python host/pico9918_probe.py --port COM8 --output reset-5ms.json powerup --reset-ms 5
```

Each cycle releases SWD and bus outputs, removes target power for `--off-ms`
(default 1000), asserts host **/RST LOW before power-on**, switches power on,
then releases /RST after `--reset-ms` (default 10). With zero reset hold it
skips assertion. There is no normal ARM 100 ms settling delay in this test.
The probe then repeatedly writes and reads eight changing bytes at VRAM
address zero, using conservative bus timing. A status read clears any partial
control latch between attempts. Two consecutive correct transactions with
different data are required, so a fixed/floating byte or old VRAM pattern does
not count as readiness. This test overwrites VRAM bytes 0..7 and reads status.

The probe timestamps POWER_EN and reset release locally. Reports contain
the first successful transaction's start/end, confirmation time, last failed
attempt, and **min/median/max time both from power-on and from reset release**.
Only confirmed cycles enter the statistics; timeouts are counted separately.
`--timeout-ms` defaults to 2000 from power-on and must exceed reset hold.
The power cycle leaves the target powered and armed, including on a readiness
timeout. Transport/abort failures release it. Prior bus timing is restored.

This measures **first verified host-bus readiness under repeated polling**,
not an exact instant the firmware became ready. Transaction duration and
probe scheduling determine the measurement granularity; USB response latency
is outside the measured interval. A failed transaction can straddle startup,
so its timestamp is not a strict lower bound. Startup could continue after a
first successful transaction; confirmation only covers the next transaction.

Power-on means the commanded switch edge, not a sensed supply threshold.
There is no voltage sensing to prove complete discharge; increase `--off-ms`
if needed for the fixture. Manual-jumper mode is refused. Host /RST is not
the target MCU RUN pin: the present target firmware handles its falling edge,
so holding it low across boot must not be assumed to hold the MCU in reset.
The test waits until release before sending commands and makes no assertion
about whether commands would be accepted while /RST is low.

## Digital captures and drive strength

```powershell
python host/pico9918_probe.py --port COM8 capture --trigger 12 --read 16 --vcd read.vcd
python host/pico9918_probe.py --port COM8 capture --trigger 13 --write 55aa55aa --vcd write.vcd
python host/pico9918_probe.py --port COM8 raw DRIVE 2 0
```

Capture records GP4..21 into 1024 samples at `16 ns * divider`; trigger is
selected GPIO LOW (/CSR 12, /CSW 13, /INT 18), with no pretrigger buffer.
It will trigger immediately if the selected line is already low. Open the VCD
in a waveform viewer. To capture a custom command, use `TRACE`, run that
operation, then retrieve `DUMP` chunks from a Python program. `CANCEL` releases
the capture. GP16/17 are unused and their floating values are not test results.

`DRIVE` accepts 2/4/8/12 mA and slew 0=slow or 1=fast for data/MODE/strobes.
It changes output drive strength, **not the output voltage**. Actual weaker
logic levels require external hardware. The trace is a digital observation,
not an analog threshold, overshoot or ringing measurement.

## Wire protocol

One ASCII line: positive decimal request ID, command, arguments. Reply is one
JSON line with matching `id`, boolean `ok`, and result fields or `error`.
All integers are decimal; data and event words are hex without `0x`.

| Command | Arguments |
|---|---|
| INFO / STATE / OFF / CANCEL | none |
| ARM | MANUAL or SWITCH |
| READ | port 0..3, byte count 1..256 |
| WRITE | port 0..3, hex bytes |
| TIMING | none to query, or setup pulse hold divider |
| STRESS | read=1/write=0, byte count 1..16384, uint32 seed |
| BOOT | off ms 100..10000, timeout ms 1..10000, reset hold ms 0..1000, uint32 seed; timeout > reset hold; ARM SWITCH required |
| EVENTS | divider 1..64, 1..64 concatenated 8-digit hex event words |
| DRIVE | mA, fast 0/1 |
| RESET | low duration 1..1000 ms |
| CLOCKS | measurement window 1..1000 ms |
| WAIT | /INT level 0/1, timeout 0..1000 ms |
| TRACE | samples 1..1024, divider 1..65535, trigger GPIO |
| DUMP | sample offset, count 1..128 |

Event word: bits 0..7=data, 8=/CSR, 9=/CSW, 10=MODE, 11=physical MODE1,
12..19=data output enable (00 or FF), 20..31=duration minus 7.
The first and last events must have both strobes inactive; the last must
release data. The firmware rejects read contention and simultaneous strobes.
Sample bytes correspond one-for-one with event words.

Commands are never automatically retried, since a timed-out write may already
have executed. USB serial BREAK requests emergency release/power off.

## Validation and limits

```powershell
python -m unittest discover -s host/tests -v
# Native GCC, not the Arm cross compiler:
gcc -std=c11 -Wall -Wextra -Werror '-DPROBE_VERSION="test"' -Isrc host/tests/protocol_test.c src/pico9918_protocol.c -o protocol_test
./protocol_test
gcc -std=c11 -Wall -Wextra -Werror -Isrc host/tests/boot_test.c src/pico9918_boot.c -o boot_test
./boot_test
```

The Python tests interpret the actual PIO instructions to check setup, pulse,
hold, sample offsets and direction safety; exercise fragmented/error replies;
and inject data/address/prefetch/IRQ/reset faults into a reference port model.
The C tests run the production parser against boundary and malformed inputs.
They also exercise the actual power-up algorithm with delayed/unstable readiness,
reset hold, timeouts, aborted transfers, manual-power rejection and timer wrap.
These validate software; **physical target tests and OpenOCD connectivity have
not yet been run with this new fixture**. No measured maximum host speed is
claimed. Video quality, analog margins, temperature and absolute pad timing
need appropriate external measurements.
